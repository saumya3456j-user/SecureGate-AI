BACKGROUND & MOTIVATION

The Flaws in Legacy RFID Systems

Why traditional turnstiles and keycards fail in modern security environments

1. Card Cloning Vulnerability
  • Standard 13.56MHz and 125kHz cards broadcast unencrypted hardware UIDs.
  • Handheld RFID copiers costing $10 can duplicate employee badges in under 3 seconds.
  • Physical badges can be skimmed through wallets in crowded hallways or cafeterias.
  • Possession of plastic card does NOT equal identity verification.
2. Lost or Stolen Badges
  • If an authorized member drops their badge, anyone finding it gains physical perimeter entry.
  • There is zero secondary prompt at the door to verify the human tapping the card.
  • Revocation delays create critical security windows where unauthorized entry is trivial.
  • Institutions suffer billions in inventory and intellectual property theft annually.
3. Siloed Offline Logs
  • Traditional controllers log data on local micro-SD cards with zero cloud connectivity.
  • Security officers have no real-time visibility into unauthorized tap patterns.
  • No automated alert is ever sent to the genuine cardholder when their card is tapped.
  • Visitor logging still relies on vulnerable paper guestbooks and manual stamps.
CORE INNOVATION

The SecureGate AI Dual-Layer Defense

Combining physical possession with cryptographic real-time ownership proof

🛡️ Layer 1: Hardware RFID Identification
  • Physical Proximity Check: Cardholder taps 13.56 MHz RFID badge (MIFARE Classic 1K / ISO 14443A).
  • High-Speed SPI Interfacing: ESP32 captures the unique 4-byte hardware serial number (UID).
  • Audio-Visual Feedback: Instant active buzzer pulse and dual-LED feedback acknowledge card presence.
  • Cloud Lookup: Transmits UID via REST API to query enrolled MongoDB user profiles.
🔐 Layer 2: Cryptographic 2FA OTP Protocol
  • Zero Trust Enforcement: Card possession alone NEVER releases the locking mechanism.
  • Dynamic 6-Digit Code: Cryptographically generated integer with 16-byte random salt and SHA-256 hash.
  • Multi-Channel Dispatch: Sent immediately to cardholder's private Gmail and mobile SMS.
  • Anti-Replay Invalidation: 5-minute strict TTL and single-use invalidation upon submission.
  • Fail-Secure Actuation: SG90 servo unlocks to 90° for exactly 3 seconds only after OTP passes.

MFRC522 RFID SPI Wiring Table

Actuator & Telemetry Peripheral Pinouts

  • Green LED ➔ GPIO 2 (Active HIGH: Access Granted indication)
  • Red LED ➔ GPIO 4 (Active HIGH: Access Denied / Locked)
  • Piezo Buzzer ➔ GPIO 15 (Tone frequencies for alerts)
  • Servo Power ➔ External 5V / VIN Rail (Clean inductive decoupling)
CRYPTOGRAPHIC PROTOCOL

Dual-Layer OTP Verification Lifecycle

Step-by-step cryptographic sequence preventing replay attacks and brute forcing

Step 1: Scan & Ingestion
  • Card touches RC522 antenna.
  • ESP32 sends `POST /api/device/rfid-event` with hardware UID.
  • Server verifies card registration in MongoDB.
  • Unregistered cards immediately rejected and logged.
Step 2: Cryptographic Dispatch
  • Server generates random 6-digit code.
  • Generates 16-byte random cryptographic salt.
  • Stores `SHA-256(code + salt)` in MongoDB.
  • Simultaneously dispatches via Gmail SMTP & Twilio SMS.
Step 3: Verification & Pulse
  • User enters 6 digits on Gate terminal.
  • Server validates hash; marks session used.
  • Enqueues one-time `UNLOCK` command.
  • ESP32 polls, rotates servo 90°, and auto-relocks after 3s.
EDGE FIRMWARE

ESP32 Firmware Architecture & Reliability

Zero-downtime engineering designed for spotty network environments

Dual Wi-Fi Auto-Failover
  • Firmware stores primary campus Wi-Fi and secondary mobile hotspot credentials.
  • If primary signal drops, shifts to fallback hotspot within 8 seconds automatically.
  • Broadcasts fallback SoftAP setup network if both external connections drop.
Non-Blocking Polling Engine
  • Engineered 100% using non-blocking `millis()` state timers.
  • Zero blocking `delay()` calls: ESP32 core never hangs or triggers watchdog resets.
  • Independent command polling every 1.5 seconds keeps cloud commands synchronized.
Offline Emergency Whitelist
  • Integrated flash EEPROM storage caches emergency master bypass cards.
  • If cloud network is entirely down, security personnel can still open the gate offline.
  • Queues offline logs and flushes them to cloud upon internet restoration.

ADVANCED ENGINEERING

Concurrency Isolation & Anti-Spam Architecture

Solving real-world browser race conditions and sensor debounce challenges

Independent Scan Channels (Admin vs Gate)
  • Identified Edge Case: Background `user.html` tab polling the API consumed and wiped scans before `admin.html` could auto-fill the Edit User form.
  • Architectural Fix: Upgraded Device schema to track separate consumption pointers: `adminConsumedAt` vs `userConsumedAt`.
  • Result: Gate polling NEVER wipes or steals an RFID card scan intended for the Host Dashboard enrollment modal.
Tab Visibility Sleep & Debounce Protection
  • Tab Visibility Engine: `user.html` utilizes `document.hidden` to pause background polling when the user switches to other tabs.
  • Prevents Ghost Triggers: Completely eliminates unwanted OTP email dispatch while editing users in Host Dashboard.
  • Hardware Debounce: 2000ms RC522 firmware debounce + 6-second frontend duplicate cooldown eliminates sensor jitter.
  • Toast Clamping: Visible notifications capped at 3 to prevent UI banner stacking.

QUICKSTART GUIDE

Team Setup: Running the Project in 3 Minutes

Simple instructions for team members to run and demo the full system

💻 Backend & Web Console Setup
  • 1. Extract ZIP Archive: Unzip `SecureGate-AI_Complete_Project.zip`.
  • 2. Install Dependencies: Open terminal in folder and run `npm install`.
  • 3. Setup Environment: Copy `.env.example` to `backend/.env`.
  • 4. Launch Application: Run `npm start` (or `node backend/server.js`).
  • 5. Open Browser:
    • Gate Terminal: http://localhost:5000/user.html
    • Admin Console: http://localhost:5000/admin.html
    • Visitor Portal: http://localhost:5000/visitor.html
🔌 ESP32 Hardware Flashing Guide
  • 1. Install Libraries: In Arduino IDE, install MFRC522 and ESP32Servo.
  • 2. Open Sketch: Open esp32/SecureGateAI_Direct.ino.
  • 3. Network Credentials: Enter your Wi-Fi SSID and Password in lines 35-36.
  • 4. Backend Server: Set `BACKEND_SERVER` to your laptop IP or Render URL.
  • 5. Board Selection: Choose ESP32 Dev Module and Silicon Labs COM port.
  • 6. Flash & Verify: Click Upload. Tap your card to see live scans!
